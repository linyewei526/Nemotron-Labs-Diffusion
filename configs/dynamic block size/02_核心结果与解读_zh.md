# 动态 block size：核心结果与解读

> 本文把原服务器结果目录中的必要数字固化到 Git 仓库。统计默认排除 AIME24，并保持数据集等权。不同阶段的数据覆盖不同，禁止把六集 PyTorch 结果误写成九集完整结果，也禁止把当前三集 S16 冻结结果当成最终结论。

## 1. 第一阶段 PyTorch：block 缩短是否伤害靠前接收

### 1.1 数据覆盖

该实验完成 GSM8K、HumanEval、MBPP、MATH-500、AIME25、GPQA 六个非 AIME24 数据集，共 `181257` 个有效 paired round。MMLU、IFEval、LiveCodeBench-C++ 未完成，因此以下是六集等权阶段性结论。

六集平均接收长度：

|block|A均|A/L|整块通过率|
|:---:|:---:|:---:|:---:|
|4|3.6693|0.9173|81.51%|
|8|6.3570|0.7946|59.73%|
|16|10.2194|0.6387|40.56%|
|32|15.5004|0.4844|27.23%|

大 block 显著提高每轮接收长度，但接收/block 比例逐渐下降。这已经提示：大 block 更能提高算法 TPF，却未必适合 compute-bound serving。

### 1.2 总增益几乎都来自容量尾部

|block 对|总增益 Delta|容量尾部 Tail|区间衰减 Decay|接收相关 ρ|
|:---:|:---:|:---:|:---:|:---:|
|4→8|2.6877|2.6847|0.0030|0.7182|
|4→16|6.5501|6.5465|0.0036|0.6566|
|4→32|11.8311|11.8257|0.0054|0.6294|
|8→16|3.8625|3.8451|0.0173|0.8843|
|8→32|9.1434|9.1128|0.0306|0.8463|
|16→32|5.2810|5.2325|0.0485|0.9423|

解释：L8→L32 平均总增益为 9.1434，其中 9.1128 来自超过 L8 容量的尾部，区间内衰减只有 0.0306。也就是说，大 block 的优势几乎全部来自部分轮能继续接收第 9 个及以后的 token，而不是 L8 lookahead 使前 8 个 token 系统性变差。

条件生存率也支持这一点：

|条件|S 值|含义|
|:---:|:---:|:---|
|S(8,16,4)|0.9886|L16 能接收至少 4 个时，L8 也能接收至少 4 个的概率为 98.86%。|
|S(8,16,8)|0.9572|L16 能到第 8 个时，L8 也到第 8 个的概率为 95.72%。|
|S(8,32,8)|0.9431|L32 能到第 8 个时，L8 也到第 8 个的概率为 94.31%。|
|S(16,32,8)|0.9676|L32 能到第 8 个时，L16 也到第 8 个的概率为 96.76%。|
|S(16,32,16)|0.9404|L32 能到第 16 个时，L16 也到第 16 个的概率为 94.04%。|

因此动态缩块的核心风险不是“缩短后前缀普遍崩掉”，而是错误缩块会截断本来能够继续接收的长尾。

### 1.3 历史能预测接收能力，但不能精确回归长度

六集等权的历史相关性如下：

|历史特征|A8 Pearson/Spearman|A16 Pearson/Spearman|A32 Pearson/Spearman|
|:---:|:---:|:---:|:---:|
|上一轮 L16 接收|0.3830 / 0.4200|0.4820 / 0.5026|0.5443 / 0.5383|
|最近2轮接收均值|0.3979 / 0.4327|0.5098 / 0.5272|0.5896 / 0.5726|
|最近4轮接收均值|0.3998 / 0.4308|0.5213 / 0.5311|0.6163 / 0.5827|
|接收 EWMA(0.5)|0.4185 / 0.4504|0.5381 / 0.5528|0.6253 / 0.6067|
|最近4轮 confidence|0.3180 / 0.3902|0.4134 / 0.4904|0.4843 / 0.5477|

历史信号具有中等相关性，对长 block 接收能力的相关性通常更强；但直接用历史值预测精确接收长度仍不够准。六集无训练基线中，较好的 MAE 约为：

|目标|较好历史基线|MAE|中位误差|90分位误差|
|:---:|:---:|:---:|:---:|:---:|
|A8|EWMA(0.5)|1.5070|0.4337|4.5687|
|A16|EWMA(0.5)|3.4559|2.5150|8.5709|
|A32|EWMA(0.5)|8.7703|7.3151|16.6491|

所以后续不应执着于准确预测 `A32=多少`，而应直接预测有决策意义的事件，例如“L32 是否至少比 L16 多接收 5 个”。

历史特征与区间内 Decay 的相关性绝对值大多小于 0.02。由于 Decay 本身已接近零，这不是坏消息：后续策略主要预测长尾接收能力即可，无需再单独预测 block 缩短造成的靠前衰减。

## 2. SGLang 九集探索与离线搜索

### 2.1 探索数据质量

九个非 AIME24 数据集共采集 `699838` 个动态 round。旧探索链路中有 `23414` 轮因 canonical replay 或跨 block 公共前缀歧义被排除，可用 `676424` 轮，排除率 `3.35%`，低于 5% 上限。

新版 chosen-last 冻结验证已经把 replay mismatch 降为 0；完整 S8 验证仅因跨 block 极少量差异排除 `242/737458=0.03%`。因此冻结验证的数据完整性明显优于旧探索 trace。

### 2.2 历史信号排序能力

严格 prompt-hash test 上：

|默认目标|标签|阳性率|AUROC|AUPRC|
|:---:|:---:|:---:|:---:|:---:|
|S8|worth16|45.07%|0.7905|0.7791|
|S8|worth32|35.98%|0.8170|0.7567|
|S16|worth32|24.93%|0.8423|0.7342|
|S16|safe8|49.23%|0.7521|0.7185|

这说明历史信号真实存在，尤其适合排序“L16→L32 是否值得”。但 AUROC 衡量全体样本排序，不保证阈值附近或高分尾部的条件精度，也不保证冻结策略改变历史分布后仍保持校准。

GBDT 使用 confidence 特征后的上界仅为：

|标签|当前策略 AUROC|GBDT 较好 AUROC|差值|
|:---:|:---:|:---:|:---:|
|S8 worth16|0.7905|0.7953|+0.0048|
|S8 worth32|0.8170|0.8217|+0.0047|
|S16 worth32|0.8423|0.8554|+0.0131|
|S16 safe8|0.7521|0.7733|+0.0212|

因此当前主要瓶颈不是模型容量过小。增加复杂模型可能略有帮助，但无法单独解决错误升级和 on-policy 分布偏移。

## 3. S8 冻结策略：九集完整结果

### 3.1 策略

最终为 `logistic + confidence`：第一轮 L16；`P(worth32)≥0.6` 选 L32，否则 `P(worth16)≥0.6` 选 L16，否则 L8。

selection 上该策略的大精只有 `72.32%`、大浪为 `25.92%`，未满足原定 `大精≥80%、大浪≤10%`。搜索器之所以仍导出它，是因为 S8 搜索空间没有可行候选，代码选择了惩罚后效用最好的回退候选。

### 3.3 与固定 block 的同状态比较

从九集冻结 shadow 直接计算：

|方案|块均|接均|接收/块|
|:---:|:---:|:---:|:---:|
|固定 L8|8.000|5.777|0.7222|
|动态 S8|11.011|7.843|0.7123|
|固定 L16|16.000|8.533|0.5333|
|固定 L32|32.000|11.359|0.3550|

动态 S8 相对固定 L8：

- 接均增加 `35.76%`；
- block-token 增加 `37.64%`；
- 接收/block 下降 `1.36%`。

相对固定 L16：

- 接均下降 `8.08%`；
- block-token 减少 `31.18%`；
- 接收/block 提高 `33.56%`。

因此它是在 L8 与 L16 之间取折中：以明显少于 L16 的计算接近 L16 的算法 TPF，但没有在 compute-bound 效率上战胜固定 L8。当前不应直接部署为默认 L8 动态策略。

## 4. S16 策略：离线结果与当前部分冻结验证

### 4.1 策略和离线表现

最终为 `logistic + censor`：第一轮 L16；`P(worth32)≥0.6` 选 L32，否则 `P(safe8)≥0.98` 选 L8，否则 L16。

selection 上：

- L32 比例 `9.83%`；
- 大精 `89.10%`；
- 大浪 `9.23%`；
- 满足原定 selection 约束。

严格九集 held-out test 上：

|块均|接均|L8%|L16%|L32%|大精|大浪|
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
|17.6194|10.3184|0.00|89.88|10.12|79.20%|18.80%|

相对同一 held-out 状态下固定 L16：

- block-token 增加 `10.12%`；
- 接均增加 `16.36%`；
- 接收/block 提高 `5.67%`。

相对固定 L32：

- block-token 减少 `44.94%`；
- 接均下降 `15.68%`；
- 接收/block 提高 `53.15%`。

离线结果说明 L16→L32 是最值得继续的方向，但 held-out 的大浪已经从 selection 的 9.23% 上升到 18.80%，没有稳定满足 10% 目标。

### 4.3 safe8 的现状

虽然 `safe8` 在 test 上 AUROC 为 0.7521，但 `P(safe8)≥0.98` 几乎不触发。当前三集冻结验证 L8 占比约 `0.001%`，样本不足以证明 98% 安全率。

因此当前 S16 策略应理解为“默认 L16，偶尔升级 L32”，不能表述为已经找到完整的 L8/L16/L32 三档选择器。

## 5. 为什么有 AUROC 仍会有较高误升级

主要有四个原因：

1. **AUROC 是全局排序，不是高分尾部精度。**模型可以把大部分正例排在负例之前，但阈值以上仍混入不少“只多接收 0～1 个”的轮次。
2. **selection 选择了阈值，test 和冻结运行才是真泛化。**S16 selection 满足 80%/10%，held-out 已退化到 79.20%/18.80%。
3. **策略改变了自己的历史分布。**离线模型在 Markov 探索策略产生的历史上训练；冻结策略会连续保持或升级，使 `full_streak`、已知观测数等特征分布发生变化。这是典型 on-policy covariate shift。
4. **九集等权会暴露跨数据集不稳健。**MBPP/MMLU 即使升级轮少，其条件浪费率仍与大数据集等权，符合研究要求，但会让只在部分数据集有效的策略无法伪装成全局最优。

## 6. 计算量、算法 TPF 与实际 serving TPF

`块均`近似部署时每轮 draft/verify 处理的位置数量；`接均`表示每轮能够向前推进多少 token。对每轮固定两个外层 draft/verify forward 的 LinearSpec，接均变化与算法 TPF 方向一致。

但当前观察实验每轮执行 L8+L16+L32 三个反事实分支，并且为了正确性关闭 CUDA Graph：

- 观察进程的实际 GPU 工作远大于策略部署工作；
- 日志中的外层 forward 计数不会完整反映内部 shadow 成本；
- 当前墙钟吞吐和延迟不能用于判断动态策略部署性能；
- 完整 S8 观察运行的九集等权表观 TPF 约为 `4.508 token/forward`，但这个绝对值不应直接与普通无 shadow baseline 比较。

部署后只有策略选中的一个 block 会执行。若按 block 分桶且桶内无额外 padding，大 batch compute-bound 下，`接均/块均` 才能作为一阶吞吐方向；最终仍需真实无 shadow serving 实验确认调度和 kernel 效应。

## 7. 当前证据支持的结论强度

|结论|证据强度|说明|
|:---:|:---:|:---|
|缩块不会系统性破坏靠前接收|强|六集同状态 Decay 接近 0，条件生存率高。|
|历史能预测下一轮接收能力|强|九集严格 test AUROC 约 0.75～0.84。|
|动态 block 历史可以被正确表达|中强|完整 S8 冻结验证真实使用动态 canonical 和删失特征。|
|当前 S8 策略适合部署|不支持|大浪 29.55%，相对固定 L8 的 compute 效率略降。|
|当前 S16→L32 策略适合部署|待定|离线方向正，但九集冻结尚未完成，三集收益很小。|
|已经能安全从 L16 降到 L8|不支持|动作几乎不触发，没有足够安全尾部证据。|
|已经获得真实 serving 加速|不支持|尚未进行无 shadow、分桶连续 serving 测试。|
