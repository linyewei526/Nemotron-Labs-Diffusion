## 3. 不迁移 NLD_results 时会失去什么

本目录已经保留方法、关键数字和研究判断，但以下内容无法由 Markdown 完整替代：

- 每轮的 L8/L16/L32 position confidence、margin、entropy；
- 每个 request 的动态 action/history 序列；
- 精确训练好的逻辑回归均值、标准差、全部系数和截距；
- 对新标签、新阈值或新策略做任意离线重算的能力；
- 正在运行的 S16 任务断点。

如果完全不搬任何结果文件，新服务器可以从头运行同一实验，但不能无损续跑原服务器的冻结验证，也不能精确复现现有 policy score。

若允许只迁移小文件而不迁移庞大 trace，建议至少保留：

|文件|约大小|用途|
|:---:|:---:|:---|
|`policy_s8.json`|16 KiB|精确恢复当前 S8 逻辑回归。|
|`policy_s16.json`|12 KiB|精确恢复当前 S16 逻辑回归。|
|`search_results.json`|64 KiB|保存搜索、test 信号和全部策略摘要。|
|`validation_s8.json`|16 KiB|保存九集 S8 完整统计。|
|`settings.json/md`、`run_state.json`、`report.md`|较小|保留原命令、进度和人类可读报告。|

如果这些也不迁移，应以本目录记录为研究交接依据，并在新服务器重新采集 trace、重新训练策略。

## 4. 当前方案评估

### 4.1 可以保留的设计

- 当前轮决策严格只看历史，避免当前 shadow 标签泄漏；
- 动态 canonical 历史和同状态反事实标签的采集协议；
- `数据集等权 -> request 等权 -> request 内轮次等权`；
- prompt-hash request 级 train/selection/test 切分；
- 对 L8/L16 动态整块通过采用删失感知特征；
- 大块标签同时要求绝对增益和单位额外 block 收益；
- chosen-last、分支同步和 trace 原子提交等正确性修复；
- 冻结策略必须真实重跑，不能只报告离线 test。

### 4.2 当前不足

- S8 搜索没有找到满足 80% 大精、10% 大浪约束的候选；
- S16 selection 到 test 已出现明显条件浪费率退化；
- 探索策略历史与冻结策略 on-policy 历史存在 covariate shift；
- `P(safe8)` 排序能力不足以支持高覆盖安全下调；
- 两个独立 worth 模型没有单调约束，例如可能出现 P(worth32) 高、P(worth16) 低；
- 当前搜索阈值最高只有 0.98，对极保守升级可能不够；
- `接均/块均` 只近似 compute-bound 成本，没有建模桶等待、batch 填充、KV 和 kernel 效率。

## 5. 推荐的下一阶段

### 阶段 A：完成并审计 S16 九集冻结验证

在做任何策略修改前，先取得九集全样本且数据集等权的：

- L8/L16/L32 动作比例；
- 块均、接均、接收/block；
- 大精、大浪；
- 相对固定 L16 和固定 L32 的接收与计算变化；
- 各数据集以及九集宏平均；
- trace replay/common-prefix 排除率。

若九集大精仍低于 80%或大浪高于 10%，当前策略不应直接进入部署。

### 阶段 B：on-policy 数据聚合与重新校准

冻结 S8/S16 运行已经产生策略自身分布下的动态历史。下一轮搜索可采用：

1. 将 request 继续按 prompt hash 严格切分；
2. 训练部分聚合探索 trace 和 on-policy trace；
3. selection 重新选标签和阈值；
4. 保留从未用于选择的独立 request 或新一轮真实运行作为最终验证；
5. 禁止直接在全部冻结验证数据上调阈值后再把同一数据称为最终 test。

阈值建议扩展到 `0.98、0.99、0.995、0.999`，允许模型在不确定时保持默认 block。还应设置最小升级覆盖率或报告置信区间，防止只触发极少样本时得到虚高精度。

### 阶段 C：优先收敛 L16/L32 两档

当前证据最支持：

```text
默认 L16
连续整块通过/历史高接收能力形成高置信信号时升级 L32
一旦非满块或高置信条件消失，回落 L16
```

可以并行比较：

- 当前逻辑回归 gate；
- 只依赖 `full_streak + nonfull_streak + 长窗接收均值` 的可解释迟滞规则；
- 预测连续收益 `A32-A16` 后按保守下置信界决策；
- 带单调约束的模型；
- cost-sensitive 分类，直接重罚“升级但增益≤1”。

最终排序不应只用 AUROC，而应首先看：大浪、显著收益 precision、动作覆盖率、接均增益/block-token 增量。

### 阶段 D：再研究 L8 下调

L16→L8 需要预测的是“零损失”这一高要求事件。可考虑：

- 不直接预测 `A8=A16`，而预测 `P(A16>8)` 的保守上界；
- 仅在连续多轮明显低接收且没有整块删失时下调；
- 加入 conformal/下置信界式 abstention；
- 把 L8 作为低负载或极强低接收证据下的动作，而不是常规动作。

在没有足够触发覆盖率和独立验证前，不要宣称 safe8 已解决。

### 阶段 E：真实 SGLang 分桶 serving

只有策略质量达标后才实施无 shadow serving：

1. request 每轮计算 action；
2. action 相同的 request 进入 L8/L16/L32 桶；
3. 调度器从同一桶组成 batch，避免混合 block padding；
4. 只执行选中 block，不运行反事实分支；
5. 与固定 L8/L16/L32 在相同到达率、并发和输出负载下比较。

必须同时报告：

- decode TPF；
- output token/s 和 request/s；
- TPOT、端到端延迟及尾延迟；
- 实际每轮处理 token 数；
- 各桶平均 batch size、等待时间和空转比例；
- GPU 利用率与是否进入 compute-bound；
- 策略计算和调度开销。

## 6. 建议的决策门槛

在进入真实 serving 实现前，至少满足：

|条件|建议门槛|
|:---:|:---:|
|九集等权大精|≥80%，最好附 bootstrap 下置信界。|
|九集等权大浪|≤10%。|
|默认潜力损失|接收损失接近 0。|
|计算收益|接收/block 明确优于默认，而非仅有不足 1% 的波动。|
|覆盖率|有足够升级轮，不依赖极少数事件。|
|跨数据集稳定性|不能只靠 AIME25/GPQA 等少数数据集取得宏收益。|
|on-policy 验证|必须在冻结策略真实重跑上成立。|

若最终 S16 只取得类似当前三集的 `+0.28%` 接收/block，应先视为信号不足或收益过小，不值得立刻承担复杂分桶调度；若完整九集接近离线 held-out 的 `+5.67%`，则值得进入无 shadow serving 验证。
