## 1. 用户需求与研究目标

目标是在连续 serving 场景中，让每个 request 的 block size 在 `{8,16,32}` 间逐轮动态变化：

1. 每个 request 的第一轮固定使用 `block_size=16`；
2. 后续只使用当前轮开始前可获得的历史信息，预测下一轮适合使用的 block size；
3. 在不破坏或尽量少破坏下一轮接收潜力的前提下，对有明确信号表明下一轮接收能力较低的 request 使用较小 block；
4. 必须处理动态 block 带来的历史口径变化，不能继续假设历史全部来自固定 L16；
5. 可补充运行 canonical L8/L32 或同状态 shadow 分支，以获取不同 block 下的接收长度、confidence、margin、entropy 等信息；
6. 当前先设计“历史信号是否存在、如何检索及如何验证”的观察实验，serving 分桶与实际端到端效率留待信号策略确认后再做。

## 2. 当前阶段性数据给出的依据

当前 block-size shadow 实验在同一 L16 canonical prefix/KV 上真实运行 L4/L8/L16/L32。已完成结果阶段性支持：

- 缩短 block 几乎不改变靠前位置的接收能力；
- 大 block 的接收优势主要来自超过小 block 上限的容量尾部，而不是 lookahead 缩短造成的区间内 Decay；
- 六个当前已完成、参与宏平均的非 AIME24 数据集上：
  - `32→16`：`P(A32>16)=39.94%`，平均 `Tail=5.2325`，平均 `Decay=0.0485`；
  - `32→8`：`P(A32>8)=57.38%`，平均 `Tail=9.1128`，平均 `Decay=0.0306`；
- L16 历史与下一轮 `A32` 存在中等偏强相关：
  - 上一轮 A：Pearson/Spearman 为 `0.5443/0.5383`；
  - 近 4 轮 A 均值：`0.6163/0.5827`；
  - A 的 EWMA：`0.6253/0.6067`；
  - 近 4 轮 confidence：`0.4843/0.5477`；
- 直接用历史值精确回归 `A32` 的 MAE 仍约为 `8.77`，因此历史更适合判断是否跨过 8/16 门槛，不适合预测精确接收长度；
- 简单只读探索中，固定 L16 历史的 `a_ewma05<=4` 覆盖约 `9.34%` 的轮，其中 `P(A32<=16)` 约为 `90.76%`，但严格 `A16>=A32` 的比例约为 `80.26%`。这说明 `32→16` 有机会，但单一阈值尚不能作为最终策略；`32→8` 需要更强组合信号。

以上数字仍是阶段性六数据集等权结果，最终结论必须等待九个非 AIME24 数据集并在独立 request 上验证。

## 3. 不预测精确 A，改为预测缩块风险

将 `A32` 视为动作集合 `{8,16,32}` 内的最大 block 接收潜力参照。同一轮同一状态分别获得 `A8、A16、A32`。

对候选 `L∈{8,16}` 定义：

```text
容量越界事件：A32 > L
实际接收损失：Loss(L) = max(A32 - A_L, 0)
严格无损事件：A_L >= A32
```

策略需要估计：

```text
q_L = P(选择 L 会产生实际接收损失 | 当前历史)
r_L = E[Loss(L) | 当前历史]
```

决策形式：

```text
如果 q8 和 r8 均满足风险约束：选择 8
否则如果 q16 和 r16 均满足风险约束：选择 16
否则：选择 32
```

最终不以普通分类 accuracy 作为主目标，而以“无损率/损失约束下可以覆盖多少缩块轮次”的风险—覆盖率前沿作为主结果。

## 4. 核心实验：动态 canonical 历史 + 同状态三分支 shadow

所有 request 第一轮固定选择 L16。每个后续解码轮执行：

```text
H_t：只由此前真正提交分支构成的可部署历史
  ↓
行为策略在看不到本轮结果前预先选择提交动作 L_t
  ↓
从同一 prefix、KV、seed/RNG 状态分别运行真实 L8/L16/L32 draft+verify
  ↓
记录 A8/A16/A32、逐位置 token、confidence、margin、entropy 等反事实标签
  ↓
仅提交预先选择的 L_t 分支，丢弃其余 shadow cache
  ↓
仅用提交分支在部署时可获得的信息更新 H_(t+1)
```

必须满足：

- `L_t` 的选择不能使用本轮任一 shadow 结果，避免标签泄漏；
- 未提交分支只提供当前轮监督标签，不能进入下一轮历史；
- temperature 固定为 0，所有分支从严格相同状态开始；
- 继续使用 EOS、剩余 budget、cache clone 和 token 一致性检查；
- 记录行为动作概率和全部 block 转换，便于检查数据覆盖及后续离线评估。

该设计既产生真实的动态 block 历史，又能在每个实际访问的动态上下文上精确得到三种候选动作的单步反事实结果。

## 5. 探索行为策略与转换覆盖

信号搜索数据不能由待评估的确定性策略自身产生，否则会出现策略选择偏差和自确认。采集阶段使用带最小探索概率的分层随机行为策略：

- 第一轮固定 L16；
- 后续较高概率保持当前 block；
- 一部分概率移动到相邻 block；
- 保留小概率跨级探索；
- 通过配额或在线计数保证下列九种转换均有足够样本：

```text
8→8   8→16   8→32
16→8  16→16  16→32
32→8  32→16  32→32
```

探索阶段不以运行效率为目标，而以覆盖不同历史状态、避免动作和阶段混淆为目标。

## 6. 动态 block 历史的右删失问题

不能把不同 block 下的 A 直接放进同一个 MA/EWMA：

```text
L=32,A=8：较明确地说明该轮接收能力低
L=8,A=8：只能说明能力至少达到 8，真实 A32 可能是 8，也可能是 20+
```

如果把两者都视为数值 8，小 block 会制造低历史，再促使策略继续选择小 block，最终产生自我锁死。

每个提交轮至少记录：

- `L`：实际选择的 block；
- `A`：实际接收长度；
- `full`：是否 `A=L`；
- `headroom`：非 full 时的 `L-A`；
- 首次错误位置；
- accepted token confidence 的均值、最小值、末位值；
- 首个 rejected token 的 confidence、margin、entropy；
- 连续 full/非 full 轮数；
- response 已生成 token 数及当前解码阶段。

围绕门槛 8/16 建立删失感知状态：

- 只有某轮 block 足够大且结果跨过/未跨过门槛时，才更新该门槛的已知证据；
- 小 block 整块通过但无法判断更高门槛时标记为 `unknown`，不能作为负样本；
- 分别维护超过 8/16 的近期概率、最近一次可确定失败位置、已知/未知观测数和 token 距离 EWMA；
- full 是“能力被当前 block 截断”的证据，应触发上探或提高下一轮 block，而不是把 A 当成精确能力上限。

## 7. 跨 block 可比较的 confidence 特征

动态 block 下，整块 confidence 均值会受到 block 长度影响。特征分为两类。

### 7.1 固定公共前缀特征

由于最小 block 为 8，优先记录所有 block 都存在的前 1/2/4/7 个 draft 位置：

- confidence 均值、最小值、末位值；
- top1-top2 margin；
- entropy；
- confidence 随位置的下降斜率；
- selected-is-top1 和 token agreement。

这组特征最适合作为跨 block 通用历史信号。

### 7.2 动作相关特征

- 实际 block 的 accepted confidence 聚合；
- 首个 rejected 位置的 confidence/margin/entropy；
- 后半段 confidence 变化；
- 特征可用性 mask 和对应 block size。

搜索时按特征组消融：仅接收历史、接收+删失状态、接收+confidence、接收+confidence+趋势/波动。

## 8. 是否补充固定 L8/L32 轨迹

可补充以下控制实验：

```text
canonical 固定 L8  + shadow L16/L32
canonical 固定 L16 + 复用当前已有 shadow 数据
canonical 固定 L32 + shadow L8/L16
```

用途：

- 校准不同 canonical block 下 confidence 和接收历史的尺度；
- 检查特征是否真正具有 block 不变性；
- 观察纯 L8、L16、L32 历史分布；
- 检查模型是否过度依赖固定 L16 历史。

固定轨迹不能覆盖真实 block 切换历史，因此优先级低于动态随机 canonical。资源有限时优先运行动态随机 canonical，其次固定 L32 控制，再次固定 L8 控制。

## 9. 信号与策略检索

### 9.1 可解释规则空间

搜索：

- 历史窗口 1/2/4/8；
- 按轮 EWMA 与按已生成 token 距离 EWMA；
- 接收均值、趋势、方差、极差；
- 连续 full/低接收轮数；
- 最近一次非 full 的错误位置；
- confidence/margin/entropy 阈值；
- 下调所需连续证据轮数；
- full 后的上调方式；
- 仅相邻转换或允许直接 `8↔32`；
- 上下调滞回和冷却轮数。

### 9.2 概率模型上限

依次尝试：

- 校准逻辑回归；
- 单调分段模型或 GAM；
- 浅层决策树；
- GBDT 作为“现有特征可达上限”。

如果复杂模型明显更好，再通过特征重要性、部分依赖和浅层树蒸馏成可解释规则。最终策略必须使用一套跨数据集全局参数，不为各数据集分别调阈值。

## 10. 候选动态策略骨架

策略采用“下调保守、上调积极、不确定时用大 block”的非对称原则：

```text
初始：16

当前为 32：
  高置信低接收证据 → 16
  极强低接收证据 → 8
  否则保持 32

当前为 16：
  full 或高接收信号 → 32
  连续低接收证据 → 8
  否则保持 16

当前为 8：
  full → 至少上调到 16
  强高接收信号 → 32
  非 full 且低 confidence → 保持 8
```

以上只是待搜索骨架；是否允许跨级跳转、连续证据轮数和风险阈值均由验证集风险—覆盖率前沿决定。

## 11. 数据切分与全局权重

- 必须按 request 划分 train/validation/test，不能按 round 随机切分；
- 同一 response 的相邻轮不能跨集合，避免时序泄漏；
- 最终排除 AIME24，使用其余九个数据集；
- 每个数据集等权，不能把所有 round 池化；
- 数据集内建议 request 等权、request 内 round 等权，避免长 response 占据过大权重；
- 使用一个全局策略、一套全局阈值，不把 dataset id 作为策略输入；
- 同时报告九数据集宏平均、最差数据集及 leave-one-dataset-out 泛化结果。

## 12. 评估指标

### 12.1 信号预测

对 L8/L16 分别记录：

- 损失事件 AUROC/AUPRC；
- 概率校准误差；
- 不同风险阈值下的缩块覆盖率；
- `P(A32<=L | 选择L)`；
- `P(A_L>=A32 | 选择L)`；
- 有损轮率；
- 平均/P50/P90/P95/P99 `Loss(L)`；
- 可安全缩块机会的召回率；
- 宏平均、最差数据集和 request bootstrap 置信区间。

### 12.2 动态策略

- L8/L16/L32 选择占比；
- 九种转换计数与占比；
- 平均 block size；
- 每轮平均接收长度；
- 相对同状态 L32 的平均接收损失；
- 连续有损轮长度；
- 错误下调后恢复到 L16/L32 的轮数；
- 小 block full 后继续停留小 block 的比例；
- 每生成 token 的理论 draft/verify 计算 token 数；
- TPF 变化及最终端到端 serving 指标（后续阶段）。

主报告给出完整风险—覆盖率前沿，例如：

```text
严格无损率至少 99% 时，最多能覆盖多少缩块轮？
平均损失不超过 0.05 token/轮时，平均 block 能降到多少？
最差数据集无损率至少 98% 时，L8/L16/L32 的比例如何？
```

## 13. 建议的实际执行阶段

### 阶段 A：复用当前固定 L16 数据预筛

- 构造 L8/L16 缩块风险与损失标签；
- 筛选候选历史窗口、趋势、波动和 confidence 组合；
- 仅用于缩小搜索空间，不作为动态策略最终结论。

### 阶段 B：动态探索数据采集

- 所有 request 第一轮 L16；
- 动态随机行为策略产生变长历史；
- 每轮真实运行 L8/L16/L32 shadow；
- 只提交预选分支，只用提交历史更新状态；
- 可先在多个性质不同的数据集子集上开发，最终覆盖九个非 AIME24 数据集。

### 阶段 C：离线检索并冻结策略

- 按 request 切分；
- 检索规则和概率模型；
- 基于九数据集等权验证目标选择风险—覆盖率 Pareto 策略；
- 冻结全部特征、阈值和状态更新规则。

### 阶段 D：独立动态策略验证

- 新 request 上从 L16 开始，由冻结策略实际驱动 canonical block；
- 继续保留 L8/L16/L32 shadow 作为反事实评估，但不能反馈给策略；
- 与固定 L8/L16/L32、简单 EWMA、删失感知规则和单步 oracle 比较；
- 最终在九个非 AIME24 数据集上等权报告。

至少需要探索数据运行和冻结策略验证两次正式运行，不能在同一批数据上一边搜索一边宣布最优。

## 14. 当前结论与后续恢复入口

1. 实验可行，现有结果已经证明历史接收状态具有预测下一轮接收能力的信号；
2. 当前固定 L16 trace 可用于预筛，但不能直接证明动态策略有效；
3. 最关键的新数据是“动态 canonical 历史 + 同状态 L8/L16/L32 shadow 标签”；
4. 动态历史必须显式建模 `L、A、full、unknown`，避免右删失造成小 block 自我锁死；
5. 第一版可部署策略最可能先实现高置信的 `32→16`，L8 是否值得使用取决于独立测试上的风险—覆盖率；
6. 信号策略确认后，再进入按 L8/L16/L32 分桶 continuous batching 的 SGLang serving 实现与实际性能验证；
7. 后续继续本任务时，应先重读本文、前置 shadow 实验手册及当时最新的完整 `report.md`，核对九数据集是否已经全部完成，再确定动态探索实验的具体超参数和实现目录。
